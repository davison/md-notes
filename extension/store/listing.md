# Chrome Web Store listing

Every field of the store listing for **md-notes**, so the listing is something
this repository holds rather than something somebody typed into a web form once
and cannot reconstruct. The Web Store API can upload a package; it cannot set
any of the fields below. They are entered by hand, from here, and this file is
what they are entered from — so when one of them has to change, it changes here
first and the dashboard is brought into line, never the other way round.

Written for davison/md-notes#135 (M8-R2). The screenshots beside it are
regenerated by `screenshots.mjs`; see `README.md` in this directory for which
field each file goes in.

### Summary

The short description, 132 characters at most. This is 116.

```
Clip web pages into your own markdown notes, and open local .md files in the md-notes app. Your files, your machine.
```

### Description

```
md-notes is the browser half of a small, local note-taking tool. The notes are
plain markdown files in a folder on your own computer, served by a program you
run yourself — there is no account, no cloud and no server of ours. This
extension does two things with it.

CLIP A PAGE INTO YOUR NOTES

Press the toolbar button, or right-click the page, and choose Clip page or Clip
selection. The extension runs Mozilla's Readability over the page first, so what
you keep is the article rather than the navigation, the sidebar and the footer,
and converts it to markdown with Turndown: headings, lists, links, tables,
fenced code with its language, block quotes, bold and italic. Clip selection
converts exactly what you have selected and nothing around it.

You see the title and the address it came from before anything is written, in a
field you can edit, and nothing is saved until you press Save. The note lands in
clips/ in your notes folder, named for the date and the title, with the source
URL and the date in its frontmatter — a file you can grep, edit in any editor,
and put in git.

OPEN LOCAL MARKDOWN FILES IN THE APP

Turn on "Allow access to file URLs" and a .md file you open from your file
manager, your terminal or a link stops being a wall of plain text in a browser
tab: it opens in md-notes, rendered, with the rest of your notes beside it. If
the file is inside a folder md-notes already knows about it goes straight there;
if it is not, the extension offers to add that folder.

WHAT LEAVES YOUR BROWSER

One address: the daemon URL you type on the options page, which is a program on
your own machine (http://localhost:7337 by default, or your own machine reached
over Tailscale). Page content goes there and nowhere else. The extension stores
exactly two things, the address and the token that program printed for you. No
analytics, no telemetry, no remote code, no third party, and nothing at all
reaches the author. The privacy policy says the same thing at greater length and
is a file in the repository, with its whole history public.

The extension reads a page only at the moment you invoke a clip on that page. It
registers no content scripts, so none of its code is running in the pages you
browse.

WHAT YOU NEED

The md-notes daemon, running on your machine. It is a single Go binary, free and
open source (MIT), installed from the Arch User Repository, a .deb, or built
from source:

  https://github.com/davison/md-notes

Run it, run "mdn token", paste the token into this extension's options, and both
of the above work. The whole of the configuration is those two fields.

Open source, MIT licensed, and the source of the extension you are installing is
in that repository, tagged at the version you are installing.
```

## Privacy tab

### Single purpose

```
md-notes has one purpose: to put what you are reading into your own notes, and
to open your own notes in the app that reads them. Everything the extension does
is one of those two acts — converting the page or selection you asked for into
markdown and sending it to the note-taking daemon running on your machine, or
noticing that a tab has navigated to a local markdown file and opening that file
in the same daemon's reader instead of leaving it as plain text.
```

### Privacy policy URL

```
https://github.com/davison/md-notes/blob/main/docs/privacy.md
```

### Permission justifications

One box per permission in the dashboard. Each of these is the whole
justification for that box.

**`storage`**

```
The extension stores exactly two values: the URL of the user's own md-notes
daemon and the bearer token that daemon printed for them. Both are entered by
the user on the options page and both are needed on every request the extension
makes to that daemon. Two further values are held in session storage, which is
discarded when the browser closes: the clip the user has prepared but not yet
saved, which must survive the service worker being shut down between preparing
it and pressing Save, and a one-line reason for whatever the toolbar badge is
showing, per tab. Nothing is stored about the pages the user visits.
```

**`contextMenus`**

```
The extension adds two entries to the page's right-click menu: "Clip page to
md-notes" and "Clip selection to md-notes", which is the second of the two ways
a user starts a clip. Nothing else is added to any menu.
```

**`activeTab`**

```
Clipping a page means reading that page. activeTab is how the extension reads
the one tab the user has just invoked it on, at the moment they invoke it, and
loses that access again when the tab navigates. It is used in preference to a
broad host permission precisely so that the extension can read the page the user
asked it to clip and no other: the extension registers no content scripts, so
outside that moment none of its code is running in any page.
```

**`scripting`**

```
The conversion has to happen in the page. Mozilla's Readability needs a live DOM
to decide what the article is, and a text selection exists nowhere but the tab
that holds it, so the extension injects its extractor and markdown converter
into the one tab activeTab has granted it, runs them there, and takes back
markdown. activeTab says which page may be read; scripting is what allows any
code to run in it at all. No script is injected into any tab the user has not
invoked a clip on.
```

**Host permissions** (`http://localhost:7337/*`, `http://127.0.0.1:7337/*`, `file:///*`)

```
http://localhost:7337/* and http://127.0.0.1:7337/*: the extension's whole
purpose is to talk to the md-notes daemon, which is a program the user runs on
their own computer and which listens on that port by default. This is where
clips are sent and where notes are read from. Chromium enforces the port, so the
grant reaches that one service and no other program on the machine.

file:///*: to notice that a tab has navigated to a local markdown file, so that
file can be opened in the md-notes reader instead of being shown as plain text.
The extension reads the address of such a tab and nothing else; it never reads
the contents of the filesystem, and it registers no content script on file URLs.
This permission is inert until the user separately switches on "Allow access to
file URLs" for the extension, which Chromium requires and which the extension's
options page explains. It is requested in preference to the alternative — the
"tabs" or "webNavigation" permission, either of which would report every
navigation in the browser — because file:///* limits what the extension sees to
exactly the case it acts on.
```

**Optional host permissions** (`http://*/*`, `https://*/*`)

```
Not granted at install, and never requested unless the user changes the daemon
URL. The md-notes daemon does not always listen at the default address: a user
may run it on another port, or reach their own machine over a Tailscale network
under an https name. There is no way to know that address in advance and no way
to express "whatever the user typed" as a manifest pattern, so the extension
asks the browser for permission for the address the user has just typed, with
the browser's own prompt, at the moment they save it. Chromium will only prompt
for a pattern the manifest declares as optional, which is why the broad pair is
declared. The extension talks to the one address the user configured; granting
this does not cause it to visit anything else, and it never has.
```

### Remote code

```
No, I am not using remote code.
```

Everything the extension runs is in the uploaded package. It loads no script
from any URL, evaluates no fetched code, and uses no `eval`.

### Data usage

Declared collected: **nothing**. None of the store's categories are ticked —
not personally identifiable information, health information, financial
information, authentication information, personal communications, location, web
history, or user activity.

The token the user pastes is authentication information *for their own daemon*,
and it is neither collected nor transmitted anywhere but to the daemon the user
named; the store's disclosure asks about data collected by the developer, and
the developer receives nothing.

The three certifications are true and are certified:

- the extension does not sell or transfer user data to third parties, outside of
  the approved use cases;
- it does not use or transfer user data for purposes unrelated to the item's
  single purpose;
- it does not use or transfer user data to determine creditworthiness or for
  lending purposes.

## What the review may push back on, and the answer

Recorded in advance, because two of the permissions above are the ones store
review most often asks about, and the answer should not have to be invented
under time pressure. What the review actually says goes on davison/md-notes#135
when it lands, along with whatever changed.

**`file:///*`.** The usual objection is that a file scheme grant is broad. The
answer is above and does not need softening: the extension reads the *address*
of a tab, not the filesystem, it registers no content script on `file:` URLs,
and the permission does nothing at all until the user takes a second, explicit
step that Chromium deliberately makes awkward. The alternative — `tabs` or
`webNavigation` — would report every navigation in the browser, which is
strictly more than `file:///*` reveals. If the reviewer will not take it, the
feature it supports is the file-URL intercept and nothing else; the clipper is
unaffected, and dropping it would be a functional loss, not a cosmetic one.

**`http://*/*` and `https://*/*` as optional host permissions.** The usual
objection is that a broad host pattern is a broad host pattern whether it is
optional or not. The answer is that they are never requested unless the user
types a daemon address that is not the default, that the browser's own prompt
stands between the declaration and any grant, and that a manifest cannot express
"the address the user is about to type". If the reviewer will not take it, the
fallback is to narrow the declaration to `https://*/*` alone and tell users on a
non-default **http** port to load the extension unpacked — which would be worse
for them, and is the trade to be made only if it is made for us.

**The data-use declaration.** The listing declares nothing collected in any
category, and a reviewer may well ask how that squares with an extension that
transmits the content of a web page somewhere. The answer, if it is asked:

> The extension transmits the page the user asked it to clip to one address:
> the URL of the md-notes daemon, which the user types into the extension's own
> options page and which is a program running on their own computer. The
> developer operates no server, receives nothing, and has no means of receiving
> anything — there is no endpoint of ours in the package, and the source is
> public. The categories in this declaration ask what data the *developer*
> collects or transmits to third parties; the answer to every one of them is
> none. The user sending their own page to their own machine is the extension's
> single purpose rather than a collection of data.

Worth knowing while writing that: the program policy defines "handle" as
"collecting, transmitting, using, or sharing user data", and the User Data FAQ
says disclosure can be required even where data "is processed or stored locally
on a user's device and is not transmitted to external servers" — so the question
is not settled by the data staying on the user's own machine, and the listing
should not argue that it is. The daemon URL may also be a Tailscale name, which
is the user's own machine reached over their own network, and still nobody
else's server. If the review disagrees and asks for a category to be ticked, the
one to tick is **Website content**, with the same explanation in the
justification field; nothing about the extension changes, and the declaration
becomes more conservative than it needs to be rather than wrong.

**A daemon on `localhost`.** A reviewer with no md-notes daemon running sees an
extension that cannot do anything. The description says what is needed in its
own section, and the review notes for the submission should say it again, with
the link to the repository and the three commands (`make build`, `mdn serve`,
`mdn token`) — the point being that the extension is inert without it, not
broken.
